## Historical Judgment: Diagnose Geometry, Keep Statistical Support Unchanged

**Yes, offline native local-pocket validation is a worthwhile, limited improvement.**
The present 96-unit XY / 24-unit Z centroid neighborhood can match a cell across
a thin wall. Height separation alone cannot distinguish adjacent rooms or sides
of cover. `holdingEvidence()` in `src/range/prefire/occupancy.ts` has no native
collision/pocket check. The candidate's own placement and approach visibility
validation do not establish that its matched evidence came from the same pocket.

**Do not call the result route-conditioned probability.** Current support means
that some qualifying low-speed firearm episode occurred nearby at some time in
a sampled side/phase round. It does not mean an opponent was there when this
approach arrived, was watching that approach, or occupied the authored facing
and stance. Preplant windows vary in duration; postplant includes saves/retakes.
Native geometry can reduce spatial leakage, not supply those missing conditions.

### Diagnostic Review Contract

Keep the diagnostic as a separate offline **candidate-to-cell admissibility
mask**, reviewed before considering any change to published weights:

1. Keep the current side/phase and 96/24 tests as the broad phase. Identify a cell
   by map, side, phase, and integer bin, not its rounded centroid text. Fingerprint
   density, catalog/coordinates, collision build/hash, and gate parameters.
2. Use native **movement** collision, pawn-foot coordinates, and existing
   `sourcePoint`, `vertical`, `fits`, and `sweep` helpers. The native hull is a
   16-unit half-width cuboid, with 72/54-unit standing/crouched heights. Verify
   support and hull clearance at both endpoints; allow only the existing six-unit
   local vertical tolerance, never XY relocation or a different-floor snap.
3. Start with a conservative direct local corridor: sample supported feet at
   <=2 Source-unit horizontal intervals and sweep the hull between consecutive
   points. Do not use a long path around a wall to make two pockets equivalent.
   Bound work by the existing neighborhood and a fixed sample cap. If later
   permitting detours, use reviewed pocket labels and a pinned local path-length
   cap; whole-map nav connectivity is insufficient.
4. Distinguish `accepted-local`, `blocked-corridor`, and `ambiguous` (unsupported
   centroid, stance-dependent clearance, floor transition, straddling bin, or
   map-version uncertainty). A blocked direct corridor is not proof the real
   observations were elsewhere. Count accepted cells only in the diagnostic
   accepted-support union; retain excluded/ambiguous support separately.
   Require both test heights for unconditional acceptance because aggregate
   cells do not preserve observed stance. Crouch-only acceptance is a separate
   diagnostic, not evidence of crouched popularity.
5. Union accepted cell round keys within each candidate and family for diagnosis,
   intersect the **unchanged sampled side/phase denominator**, and leave the
   current weights and one-ticket exploration floor untouched. Report broad
   versus accepted support and distinct supporting
   matches. Never remove a sampled round from the denominator because its
   neighborhood was rejected. No accepted evidence means unknown, not unused.
6. Reject a stale/wrong-map mask explicitly; do not silently present the broad
   radius result as geometry-screened evidence. Build the mask once offline;
   leave browser-frame collision scans, target placement, and route work alone.

Do **not** require line of sight from the approaching player to the evidence
point: concealed holds are precisely what the drill trains. A bullet ray is not
a pawn-traversability test; shot and movement masks differ. A local hull corridor
is a useful operational proxy for a pocket, not proof of tactical equivalence.

**Centroid limit:** a 64x64x32 bin may contain observations on both sides of a
wall, and its mean may be embedded or on an unobserved location. Accepting its
centroid cannot certify every round attached to that bin. Do not describe the
filtered count as a formal lower bound on true same-pocket occupancy. It is a
conservative subset of the existing *centroid-matched support*. A stronger later
offline method must classify actual retained interval endpoints into native
pockets and export pocket-specific round unions, without inventing positions or
splitting a cell's round count proportionally by area/dwell. Existing cached
ticks can support that investigation; it is not implemented here.

Acceptance tests: two supported points across a thin wall fail the local gate;
same-floor open corridor passes; movement-only playerclip blocks despite a clear
shot ray; upper/lower floors never merge; an embedded mean is ambiguous; a short
legitimate around-box pocket is conservatively flagged rather than labeled
unused; duplicate cells/players/episodes count a round once; no-support families
retain exploration; stale collision/density hashes and wrong map fail closed.
Review a small set of retained real points on each side of flagged walls before
using deltas to prioritize source inspection. Passing these tests still does not
authorize promoting centroid-screened counts to new weights.

### Raw-interval Gate Before New Pocket Weights

The next gate needs the **actual retained interval feet and identities**, not a
new confidence score for bin means. Prefer a bounded read of the existing pinned
tick cache first; request new state-only source files only when the needed fields
or provenance are missing. No extra independent matches are created by reprocessing.

1. Freeze the existing acquisition/method and identify reviewed pocket boundaries
   and the source-demo map-build compatibility. Unknown source build is an
   explicit unresolved condition; a current native pass alone cannot certify old
   geometry. Pin the collision, pocket definitions, helpers, source files and
   analysis version. Preserve native XYZ; do not repair observed feet by XY nudges.
2. Reconstruct the currently retained episodes from original adjacent intervals
   with the same alive/weapon/input/speed/dwell/phase rules. Classify actual
   endpoints into native floor/pocket components using continuous supported
   connections. An interval crossing components is split only where observations
   support the boundary; do not fabricate an interpolated pause or inflate dwell.
   Keep stance unknown unless measured; independently verify equipment semantics.
3. Retain `(match-map, round, side, phase, pocket, interval)` attribution offline.
   A cell can contribute different round keys to different pockets only if actual
   retained intervals support those assignments. Never distribute all its round
   keys to every traversable sub-pocket, or allocate round counts by centroid,
   area, episode totals, or a dwell fraction. A round with real holds in two
   pockets may legitimately support both.
4. Export per-pocket exact round unions, sampled side/phase denominators, observed
   coverage, ambiguous/unassigned support, and unique supporting match counts.
   Map each validated physical family to its reviewed pocket and union supported
   keys. Do not inherit a course's approach/arrival/role labels as observed context.
5. Require conservation/reconciliation with the old retained interval totals,
   phase/death/gap isolation, multi-pocket same-bin fixtures, no double counting,
   and deterministic byte-identical offline regeneration. Manually inspect a
   bounded set of actual accepted/rejected points around thin walls, boxes, and
   floor transitions; compare method sensitivity and leave-match/event-out ranks.
6. Publish only after reviewing both spatial assignments and source rights; any
   weighting change is an explicit parent decision with an evidence revision.
   Retain exploration for unknown pockets and keep statistical and authored
   placement artifacts distinct. Until this gate passes, **leave current weights
   unchanged and disclose their radius/centroid and conditioning limitations**.

This can improve pocket-specific *observed regional support*. It still cannot
estimate encounter probability without independently measured approach arrival,
time-window opportunity, stance/facing/role, censoring, and joint occupancy data.

```text
n / N, distinct supporting matches, radius n, local n
blocked/ambiguous cells and round unions, shared-cell family pairs
per-match support numerator n_m and sampled phase denominator N_m
density/catalog/collision hashes and gate revision
```

`blocked`, `ambiguous`, and accepted round unions can overlap, so their sizes
must not be added as disjoint counts. The report can derive match attribution
from existing sampled round metadata without exporting player identities.
Start by reporting sparse one-match support; do not treat a chosen two-match
threshold as statistical confidence. This is a small parent-owned improvement
with no acquisition or new importer required.

### Weighting And Uncertainty Recommendations

- **Keep the estimand honest.** `n/N` is an any-time regional qualifying-hold
  frequency in selected rounds. It is not synchronized occupancy, number of
  opponents, win likelihood, or `P(enemy present | approach, arrival, role)`.
  The same round can support many regions. Normalized family tickets are course
  selection weights, not mutually exclusive real-world outcomes. Choosing four
  bots is a training setting; weighted sampling with compatibility constraints
  is not sampling an observed joint defensive setup.
- **Diagnose clustering before reweighting.** Compute leave-one-match-out and
  leave-one-event-out rank changes; include a repeated-team exclusion sensitivity.
  A fixed-eight-round sample already equalizes preplant round contribution per
  match, so equal-match preplant rates do not automatically fix its current bias.
  Postplant has unequal `N_m`; compare pooled `sum(n_m)/sum(N_m)` with the mean
  of `n_m/N_m` over matches having phase exposure. They target different descriptive
  populations. Do not fill undefined postplant rates with zero.
- **Uncertainty is not a tick count.** If an offline exploratory resampling band
  is useful, resample entire match clusters with all their chosen rounds and
  recompute support unions; use resampled cluster-instance keys so duplicate
  draws are not erased by a Set. Label it a within-corpus stability band, not a
  population confidence interval. Repeated teams/events remain dependence. Do
  not use binomial/Wilson/Beta precision based on 10.8 million correlated rows
  or silently treat the 256 within-match rounds as independent population trials.
- **Separate exploration from sample size.** `1+n` is a defensible declared
  practice heuristic, but duplicating a corpus under new IDs changes the relative
  strength of its additive floor. An optional trial is
  `q_f = n_f / sum(n_g)`, `p_f = (1-lambda)/K + lambda*q_f`, with uniform fallback
  if no support, one term per physical family, and a fixed declared training
  `lambda`. No value of lambda has been empirically justified here. Split a
  family's ticket across valid variants as now; do not give each stance its own
  exploration floor. This mixture preserves exploration under sample expansion,
  but still does not estimate encounter probability.
- **Resolve physical aliases, not statistical coincidence.** Reuse explicit
  canonical pocket/alias IDs across sources and fixed lineups. Audit identical
  coordinate records and near alternatives; movement incompatibility alone does
  not merge their weighting families. Do not merge all overlapping 96-unit disks
  transitively, or partition support by nearest centroid without reviewing walls,
  floors, and actual samples. A bin bridging two legitimate pockets is ambiguous;
  raw pocket-specific observations are the durable fix.
- **Condition only when data supports it.** Future time-window denominators must
  retain all predeclared sampled opportunities with usable coverage, including
  no-hold rounds and declared early-death/censoring rules. A known all-dead side
  is known zero occupancy, not missing data; an alive-conditional estimand must
  be explicitly labeled rather than silently excluding such rounds. Route
  opportunities need an
  independently defined observed attacking path/arrival event. Roles need measured
  labels and validation. Authored route names, facing, successful kills, survivors,
  or site stereotypes cannot substitute. Keep present preplant/postplant layers
  separate; do not retrofit exact-angle/site/role probabilities from this JSON.

Offline sensitivity should recompute **family round unions**, not just total
dwell: 64/96/128 XY, 16/24 Z, speed 10/20/30, dwell 0.5/1 seconds, and half-bin
origin shifts. Compare broad-radius versus local-pocket masks and flag unstable
rankings. The existing historical 48-round dwell table does not validate current
256-round support weights. Freeze all ten approaches and their reviewed families
for this comparison; a fixed-lineup choice must not redefine evidence IDs or
duplicate a family's statistical mass.

## Bounded Next-map Recipe

1. **Specify the population first:** game/build/date interval, map, mode,
   tournament versus permissioned community play, side/phase, and coarse-region
   estimand. Transfer the method, not Dust2 coordinates, rates, roles, or priors.
2. **Separate two acquisitions:** pin licensed authored coordinates with their
   notices for valid target placement; acquire independent completed-match state
   evidence for weights. OpenPrefire/retakes/Workshop bot counts are never observed
   prevalence. Keep the existing native map-authoring/route work with the parent.
3. **Rights/availability gate:** retain author, exact URL, commit/version, access
   date, license text, underlying-rights caveat, permission record, and current
   removal/gating status. Existing OpenCS2 remains declared CC BY 4.0 with its
   recorded rights qualification; this review did not independently clear its
   upstream rights. Do not treat mirrors as independent publishers or bypass a
   takedown. No alternative here is newly cleared for unconditional shipping.
4. **Metadata pilot only:** one next map, at most 8 MiB of manifests/licenses/
   indexes, no recursive clone or whole-archive loader. Inventory eligible dates,
   match-map identities, phases, all-ten-player coverage, build availability, and
   exclusion/failure reasons before inspecting positions or outcomes. With a
   larger index, stop and design a bounded server-side query, not a blind download.
5. **State pilot:** for an authorized loose-file source, at most four match-map
   recordings x four complete rounds x ten POVs, 64 MiB **total** compressed state
   inputs including metadata, with per-file reservations and decompressed-memory
   caps. These are proposed stop limits, not a promise every source will fit.
   A full raw-demo pilot is separate: request one explicitly sized permitted demo
   and approve a realistic cap before fetching. Do not force a 2-GB media shard
   through a 64-MiB state budget. Request a state-only export if necessary.
6. **Pre-register selection:** hash-rank eligible match-maps and complete rounds
   with a map-specific seed; select all ten POVs. Record source match/date/build
   and anonymous round keys plus actual bytes/SHA-256. Never select only kills,
   survivors, winning POVs, bomb plants, or famous angles and then use a global
   round denominator. Preserve zero-hold rounds and observed-coverage diagnostics.
7. **Validate source semantics:** map joins include map ID; clock/tick cadence,
   deaths/lifecycle, side swaps, weapon enum/equipment transitions, missing buttons,
   duplicate entities, gaps/teleports, coordinate origin, pawn feet, and A/B events.
   Keep sample-rate-specific methods separate. Cross-parse a permitted same demo
   to test semantics; use different matches for independent statistical validation.
8. **Validate actual raw interval feet in native pockets offline:** native map
   build/collision pin, same-floor pawn support, reviewed physical families,
   accepted/ambiguous assignments and exact unique-round unions. A centroid mask
   is a diagnostic only, not a shortcut past the raw-interval gate. Multi-level
   maps such as Nuke especially
   require floors/pockets; a 2D radar or Dust2's 24-unit tolerance is not enough.
   Incompatible demo/map versions are flagged, not silently remapped.
9. **Validate transfer:** whole-match/event/date-block holdout, cross-corpus
   overlap check, threshold/bin/pocket sensitivity, missingness and rank stability.
   If no cleared observations exist, ship only the labeled authored family prior.
   Export compact aggregate evidence plus provenance, not raw identities, demos,
   media, or Python/parser libraries. Geometry gating changes need the parent's
   targeted synthetic/native tests and normal repository validation.
